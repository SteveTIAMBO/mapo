# Fichiers de server/ à publier sur l'hébergement — LISTE UNIQUE.
#
# Lue par le workflow CI (.github/workflows/deploy.yml) et par le script de
# publication serveur (_DEPLOIEMENT-AUTO/envoyer-serveur.sh). Une seule liste,
# qu'on ne peut plus tenir à jour à moitié.
#
# ⚠️ LE DÉPLOIEMENT FRONT NE PUBLIE AUCUN .php, ET C'EST VOULU.
# Le build Vite ne contient pas de PHP : c'est ce qui garantit, par
# construction, qu'une mise en ligne du front ne peut pas écraser un fichier
# serveur ni une configuration. Une garantie structurelle vaut mieux qu'un
# filtre — un filtre se contourne par distraction.
# Les enjeux ne sont pas symétriques : un front raté se redéploie en trente
# secondes ; un mapo-ia.php cassé arrête l'IA payante, les paiements et la
# création d'écoles. Publier du serveur doit se DÉCIDER.
#
# Deux voies, toutes deux explicites :
#   • un push sur GitHub  → la CI lit ce fichier ;
#   • ./envoyer-serveur.sh --confirmer  → publication manuelle.
#
# ⚠️ N'INSCRIRE ICI AUCUN fichier de configuration (*-config.php) ni
# mapo-sa-key.json : ils vivent uniquement sur le serveur, hors du dépôt.
# Les scripts les filtrent en plus, mais la première protection est de ne
# jamais les nommer.
#
# Une ligne = un fichier. Les lignes vides et les # sont ignorés.
